# Mood Atlas — бесплатный веб-трекер настроения

Адаптивный веб-дневник самонаблюдения: регистрация по псевдониму, несколько записей в день, настроение, тревога, подавленность, возбуждение, раздражительность, энергия, сон, лекарства, факторы, заметки, календарь, история, аналитика, экспорт CSV/JSON и печать/PDF.

**Статус:** MVP. Не используйте с реальными пациентскими данными до независимой проверки безопасности, юридической документации и защиты серверной инфраструктуры. Дневник не ставит диагноз и не осуществляет кризисный мониторинг.

## Публикация на mood.biodata.health

Публикация следует проверенному паттерну Kailash Weather из актуальной
базы знаний Biodata (ревизия r2, 2026-11-10):

```text
mood.biodata.health A 62.152.38.223 (REG.RU)
  → HTTPS ingress 62.152.38.223:443
  → существующий reverse proxy 192.168.31.23
  → приватный backend 192.168.31.20:3001 (srv-prod)
```

Исходники: `/opt/mood-tracker`. В `deploy/bootstrap.sh` предусмотрена
автоматическая инициализация локального .env и ключа шифрования, а также
Docker Compose и health-check. Новое правило для hostname, сертификат и
ограничение доступа к приватному backend выполняются на существующем
общем reverse proxy, без развёртывания Nginx на srv-prod.

**[Пошаговая инструкция](deploy/README.md)** и
**[готовая заявка в поддержку](deploy/SUPPORT_REQUEST.md)**.

Схема публикации в коде ещё не означает реальную публикацию: DNS,
маршрутизация reverse proxy и установка VDS требуют подтверждённого
операторского выполнения. Не менять работающий Kailash Weather.

## Установка на домашний экран (PWA)

После публикации на HTTPS откройте Mood Atlas в браузере смартфона:
на Android — меню браузера → «Установить приложение» / «Добавить на главный экран»,
на iPhone (Safari) — «Поделиться» → «На экран Домой».
Иконка приложения и имя «Mood Atlas» задаются в `/manifest.webmanifest` и
`/icons/icon-192.png` / `/icons/icon-512.png`. Для iOS также указан
`apple-touch-icon`. Это веб-приложение без офлайн-доступа: записи загружаются
только с сервера; сервис-воркер намеренно не кэширует чувствительные данные.

## Запуск локально

Нужен Node.js 24; внешних npm-зависимостей нет.

1. Скопируйте .env.example в .env.
2. Сгенерируйте уникальный ключ командой openssl rand -hex 32, вставьте его в DATA_ENCRYPTION_KEY.
3. Запустите npm run dev.
4. Откройте http://127.0.0.1:3000.

Проверка: npm test.

## Размещение на корпоративном сервере

Для `mood.biodata.health` используйте единственную актуальную инструкцию
`deploy/README.md`. В корпоративной конфигурации Docker слушает на
`192.168.31.20:3001`, а TLS завершается на отдельном общем reverse proxy
`192.168.31.23`. Не используйте localhost-only путь как готовый маршрут
для этого отдельного proxy. Не доверяйте `X-Real-IP` от произвольных
клиентов; проверка ACL и политики IP-заголовков необходима отдельно.

## Приватность и эксплуатация

Записи шифруются на сервере AES-256-GCM; пароли хешируются scrypt. Это **не сквозное шифрование**: владелец сервера с ключом способен расшифровать данные. Сессии используют HttpOnly SameSite=Strict cookies; запросы проверяют Origin. Регистрация требует явного согласия и возраста 18+. Аккаунт можно удалить, историю — экспортировать.

Важные ограничения: пока нет подтверждения email, встроенной экстренной службы, MFA, напоминаний и независимого аудита; для восстановления нужен выданный при регистрации одноразовый код. До запуска с пациентами подготовьте юридически полную политику приватности и GDPR-процессы, DPIA при необходимости, шифрованные резервные копии, регламент удаления копий, мониторинг и процедуру реагирования на инциденты. При утрате DATA_ENCRYPTION_KEY записи не восстановить.

Вдохновение функциональностью Daylio (привычки и календарь), eMoods (отдельные симптомы и сон), Bearable (факторы и динамика) и How We Feel (простой check-in), без копирования их интерфейса.

Источники: https://daylio.net/ , https://emoodtracker.com/ , https://bearable.app/ , https://howwefeel.org/

## Дальнейшие задачи

Настраиваемые шкалы, врачебный PDF, напоминания, безопасный ограниченный по сроку доступ врачу, импорт архива, многоязычность, браузерные end-to-end тесты. Никаких платных API не требуется, но инфраструктура сайта и её обслуживание имеют стоимость.
