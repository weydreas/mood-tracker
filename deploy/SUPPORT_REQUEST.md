# Заявка в инфраструктурную поддержку: mood.biodata.health

**Задача:** опубликовать новый HTTP-сервис Mood Atlas на том же публичном
HTTPS ingress, где уже опубликован `kailas.biodata.health`. **Не изменять**
правила Kailash и других ресурсов, не делать прямой проброс TCP/3001 в интернет.

Пожалуйста, проверьте текущую схему и добавьте отдельный HTTPS host/SNI rule
для нового имени:

| Поле | Значение |
|---|---|
| Внешний hostname | `mood.biodata.health` |
| Внешний IP для DNS A в REG.RU | `62.152.38.223` |
| Публичный порт | `443/TCP` (HTTPS) |
| Существующий reverse proxy | `192.168.31.23` |
| Backend | `192.168.31.20:3001` |
| Протокол от proxy к backend | `HTTP` по корпоративной приватной сети |
| Health-check | `GET http://192.168.31.20:3001/api/health` |
| Ожидаемый ответ health | `{"ok":true}` |
| TLS-сертификат | Для `mood.biodata.health`, с продлением |
| HTTP/80 | Если включён — редирект на HTTPS |
| Backend ACL | Разрешить источник `192.168.31.23`, исключить прямой public NAT |
| Авторизация | Встроенная регистрация, логин и сессионные cookies приложения |

**Технические условия:**
- сохранить `Host: mood.biodata.health` и корректный `X-Forwarded-Proto: https`;
- перекрывать, а не слепо пробрасывать клиентские заголовки `X-Real-IP`/
  `X-Forwarded-For`; не принимать их как доверенные от клиентов;
- поддерживать cookie `Secure; HttpOnly; SameSite=Strict`, работу API с
  `Origin: https://mood.biodata.health`;
- не логировать request/response bodies, токены, cookies или медицинские заметки;
- подтвердить, что доступ к backend `192.168.31.20:3001` ограничен только
  reverse proxy и согласованными средствами внутренней диагностики;
- не открывать отдельный публичный TCP/3001.

**Важно:** в приложении предполагаются записи о психическом здоровье.
Пока использовать только синтетические аккаунты. Ввод реальных данных —
после утверждения политики данных, резервного копирования и аудита безопасности.

**Просим подтвердить по результатам настройки:**
1. Что реальный ingress по-прежнему `62.152.38.223`, а прокси —
   `192.168.31.23`, и кто владеет конфигурацией?
2. Какой сертификат/способ автоматического продления используется?
3. Что приватный health-check проходит с proxy и нет прямого public NAT?
4. Что публичный `https://mood.biodata.health/api/health` возвращает
   `{"ok":true}` из внешней сети и не открывает чужой/default сайт?
5. Что существующий `https://kailas.biodata.health/` продолжает работать
   без изменений?
